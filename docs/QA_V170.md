# v1.7.0 驗證紀錄

## 產品規則

- 只建立能從原文確認日期的個人行程。
- 購買、付款、繳費、填表、提交、取件、包裹與一般截止日不建立行程。
- 「999 秒前」「2 分鐘前」只視為通知年齡，不可作為行程日期或時間。
- 分段訊息仍須合併，例如「今天吃好吃的／在星月廣場／我們訂 20:15」應建立一筆聚餐行程。

## 自動檢查

- TypeScript 型別檢查通過。
- 83 項 JavaScript／TypeScript 測試通過，包含購買方案截圖與 AI 失敗時本機備援的回歸案例。
- Android 原生測試包含購買說明、日期型任務、分段邀約及安全背景寫入案例，由 GitHub Actions 在 APK 建置前執行。

## 人工流程

1. 首頁輸入「明天晚上 7:30 在星月廣場聚餐」，確認編輯頁自動帶入明天、19:30 與星月廣場。
2. 傳送分段聊天通知，確認只建立一筆行程。
3. 傳送包含「999 秒前、購買方案、方案金額、備註名字」的通知，確認不會出現在 App 或行事曆。
4. 傳送「9 月 20 日前繳費」與「明天 20:00 前購買車票」，確認皆被略過。
5. 傳送明確個人預約、聚餐、會議與改期通知，確認建立或更新行程，並收到結果通知。
