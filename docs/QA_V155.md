# v1.5.5 UI 與功能驗證

驗證日期：2026-09-12～13。測試平台：Windows 上的 Android 36 Pixel 模擬器；最終使用 Asia/Taipei 時區。資料、通知來源及截圖均為合成測試內容。

## 本次改版

- 暖白、深綠主色與分類色彩；重做首頁、事件編輯、詳情卡片，統一月曆、設定與監聽 App 管理頁。
- 首頁顯示下一個行程、截圖／貼上入口，以及今天、待辦、待確認、全部篩選；取消原本 10 筆待辦、4 筆待確認的顯示限制。
- 編輯頁分成名稱／分類、日期／提醒、補充細節；儲存按鈕固定於底部，支援跨日結束時間、地點及未儲存返回確認。
- 月曆支援跨日顯示、已完成項目與歷史搜尋；詳情提供完成、恢復、準備清單、修改紀錄及連結。
- 設定依監聽、提醒、AI／行事曆、資料分組收合，操作成功或失敗均顯示結果。

## 已修正的功能問題

1. 相對日期的「大後天、下週五、明晚十點半」；手動匯入以操作當天為基準，通知以收到通知的當地日期為基準。衝突時間保留待確認。
2. 截圖主題被攜帶事項蓋過，例如「牙醫回診」誤成「請帶健保卡」。
3. 全天行程的 UTC 日期與 24 小時區間、跨日行程的月曆顯示與編輯保留。
4. 快捷與手動加入手機行事曆使用同一識別；新版建立的副本可更新，避免重複新增。
5. AI 逾時涵蓋回應內容讀取；處理無效金鑰、429、無工具回應、非法日期和倒置時間。錯誤提示不轉貼可能包含敏感資料的供應商原始回應。
6. AI 失敗保留候選通知；匯入操作採單一執行流程，避免與手動儲存／清除競爭覆蓋資料。
7. 截圖辨識出的更正會套入編輯欄位；完成／取消動作經確認後實際更新。
8. 待確認事件不排程提醒；手機行事曆權限撤銷後，設定回報關閉狀態。單次加入不會順便啟用自動加入。
9. 清除資料同時清除原生監聽選擇、候選通知、對話緩衝及回覆目標。重新開啟不會因殘留設定再次匯入。
10. 過期的回覆目標不再改用其他通知猜測；回覆前要求使用者確認。避免無回覆建議時將數字 0 直接渲染到畫面。
11. 新資料存入前驗證備份格式，保留較長舊版地點與清單資料的相容性；載入時不再自行丟棄既有事件。

## 尚未驗證及使用界線

- 未使用有效付費 API key 執行真實 AI 分析；工具解析、逾時與錯誤路徑已測，實際帳戶的模型權限、額度及語意結果仍須以該帳戶驗證。
- 未向真實聊天對象送出回覆；RemoteInput 成功回覆仍需在支援此功能的訊息 App 上驗證。
- 未驗證實體手機的省電、鎖定、廠商背景限制與長時間待機，亦未進行 iOS 裝置驗證。
- 背景監聽負責收集候選通知；完整本機／AI 整理在 App 開啟時進行。原生快捷擷取可直接處理明確日期，時段不明時會要求開啟 App 確認。
- 目前預排最近 40 筆提醒，之後需再次開啟 App 補排。
- 手機行事曆是獨立副本。刪除 App 事件、取消／完成或清除資料不會刪除該副本。舊版僅保存「已加入」標记而沒有事件 ID，無法可靠更新其既有副本，會提示使用手機行事曆編輯。
- APK 使用測試簽章，提供側載驗收；此報告不表示已通過 App Store／Google Play 的正式上架審核。

模擬器中最後放置少量明確標記來源的示範資料，方便預覽。手機安裝 APK 不會包含這些資料或任何 API key。
